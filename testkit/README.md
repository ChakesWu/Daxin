# 答信 人工测试套件 v0.1

用途：以一般客户身份，通过公开渠道人工提问，把回答与公开文件核对，产出可复核的差异记录与统计。
**全程离线、人工操作。本套件不含任何访问银行系统的程序。** analyze.py 只读你填好的两个 Excel。

## 文件
| 文件 | 作用 |
|---|---|
| ground_truth_register.xlsx | 标准答案登记表：每行一个事实，带版本、来源日期、抓取日期、旧版取值（须有公开依据） |
| question_bank.xlsx | 题库（115 条）：15 个主题 × 基础、口语、错别字、三种外语、重测；3 组多轮；自我揭露与可追溯各 1 条；另含执行矩阵与禁止项 |
| test_log.xlsx | 观察记录：每次提问一行，含回答原文、截图编号、人工判定、复核判定 |
| analyze.py | 读上面三个表，输出 report.md、stats.csv、evidence_cards.md |
| templates/ | 主办方询问信、私下观察简报、试点提案 |
| private/ | 放 institution_map.csv（代号,名称）。此目录内容不得进入任何输出或仓库 |
| sample/ | 仿真样例（虚构代号 BANK-X），用来试运行程序，不是任何真实系统的结果 |

## 行为规则（先读）
1. 只做一般客户会做的事：在公开渠道里人工输入问题。不登录真实账户，不做交易，不输入真实个人信息。
2. 不批量、不用脚本、不绕过验证码或频率限制。每日提问数量保持在人工可正常完成的范围，分时段。
3. 不做越狱、提示注入、套取内部指令、压力测试。诱导式提问若要做，只在被授权的环境做，且不计入错误率。
4. 先读各渠道的使用条款。任一渠道条款禁止自动化、测试或抓取，就不要用该渠道。我不是律师；内地、香港、澳门法规不同，如有疑问请咨询律师。
5. 公开材料一律用代号（BANK-X），不点名。点名需要机构书面同意。代号对应表只放在 private/。
6. 不要为了“找到错误”改变提问方式。没找到差异就如实记录，并报告样本量和区间。

## 流程
1. 登记标准答案：只用公开文件；每行记来源日期和抓取日期；两人独立核对。
2. 选题：从题库按需要的方法与主题选；时效与区域两种方法只用在公告确有变更或确有多地区渠道的条款上。
3. 提问并记录：每次一行；回答原文整段粘贴；截图编号对应截图文件；多轮在同一会话里连续问。
4. 判定：记录人先填“人工判定”，另一人独立填“复核判定”；分歧写备注，并回到文件核对版本。
5. 运行分析：`python analyze.py --log test_log.xlsx --register ground_truth_register.xlsx --bank question_bank.xlsx --out out`
   对外使用的输出加 `--public`：程序会检查输出里是否含 private/institution_map.csv 中的名称，含则拒绝输出。
6. 对外说明前：每个“确认差异”都要核对文件版本、重测一次、两人复核。

## 判定码
通过；C1 与现行文件矛盾；C2 引用旧版；C3 混用其他产品/渠道/地区；C4 越权承诺；C5 需合规复核；不适用、无法判断、无回答（均不计入分母）。

## 统计与解读
- 差异率用 Wilson 95% 区间；零差异时只报“上限约 3/n”，不说“没有错误”。
- 不同机构、地区、渠道、语言分开看，不加总。
- 机器建议只是辅助，不参与统计。
- 样本小、渠道版本与回答随机性都会影响结果，不代表整体错误率。

## 样本量参考
- 每个渠道×地区×语言的组合至少 30 条才有参考价值；低于 30 条只作为线索，不作为结论。
- 想说“上限低于 3%”，需要零差异的 100 条。
