# 靶场（仿真）

一个**自建的、仿真的**智能客服 RAG，用来演练答信的完整流程。它**不是任何机构的系统**，知识库是虚构的（机构代号 BANK-X，产品“示例卡”，地区 R1/R2）。

| 文件 | 作用 |
|---|---|
| `kb.json` | 仿真知识库 14 段，含新旧版本与不同地区（旧版段落 `current:false`） |
| `standard.json` | 对应的“标准”条款（答信冻结用） |
| `setup_workspace.py` | 建工作区、冻结标准、自动出题 |
| `server.py` | 靶场服务，只监听 127.0.0.1；GLM `embedding-3` 向量检索 + GLM 生成；可注入故障 |
| `run_all.sh` | 三种配置各问一遍：A1 默认（旧版留在索引、不按地区过滤）、B2 分区过滤且只用现行版本、C3 年费条款的现行版从未重新索引 |

流程：`setup_workspace.py` → `daxin ask`（HTTP 适配器，默认关闭，需 `DAXIN_HTTP_ENABLED=1`，只连本机，间隔不低于 0.5 秒）→ `daxin judge`（机器判定，仅供参考）→ `daxin review-export`（盲判表：不含机器判定与配置）→ 两位复核人各自填 → `daxin review-import` → `daxin accuracy`。

重要限制：
- 这是**自建环境**，结果只能表述为“自建环境实测”，不能说成任何机构的结果。
- 故障是自己放的，所以能知道每类错误的真相；这既是优点，也意味着不等于真实世界的错误分布。
- 机器判定未经人工复核前**不算准确率**。
