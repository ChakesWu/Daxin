# 答信 (Daxin)

**银行智能客服回答的第三方验收与分级放行。** 以经确认的制度版本为唯一标准，检查智能客服的回答，并回答一个决策问题：*这个主题能不能放给 AI 自动回答，依据是什么。*

> 状态：v0.1 开发预览。所有演示数据均为**仿真**（虚构机构代号 BANK-X），不代表任何真实机构或系统，也不是任何实测结果。
> 本工具是制度一致性检查与风险提示工具，不构成法律意见，不替代法务、合规与消保部门的判断。

## 它做什么

1. **制度内核**：条款拆成带产品、渠道、地区、语言、版本与生效区间的事实；经确认后**冻结**，冻结后只能新增版本，不能修改。
2. **观察**：被测智能体的回答以**只追加**方式入库（数据库触发器强制），回答先脱敏再存，另存原文哈希。
3. **判定**：按固定顺序判为通过、C1 与现行制度矛盾、C2 引用旧版、C3 混用其他范围的规则、C4 越权承诺、C5 需合规复核；抽不到主张时是“待人工”，**绝不判通过**。
4. **放行矩阵**：按主题×地区×渠道×语言给出 L1 全自动 … L4 必须人工；只计**人工复核**过的判定；比率附 Wilson 下界；样本不足、有未关闭的高危发现、标准有了新版本而未复测、结果过期，都只会**降级**。
5. **证据与审计**：每个确认的差异一张证据卡（链式校验）；整个工作区有哈希链审计日志（可选 HMAC）。
6. **匿名**：核心只见机构代号。对外导出时检查是否含 `private/institution_map.csv` 里的名称，含则拒绝。

## 快速开始

```bash
pip install -e ".[dev]"
daxin demo --dir .daxin-demo        # 端到端演示（仿真）
python -m pytest -q                 # 106 项测试
```

演示会依次展示：冻结的条款无法被改动；对 200 余条仿真回答判定；放行矩阵；一次标准变更使放行降级；复测后恢复；证据卡与审计链校验。

## 用于真实的人工测试

`testkit/` 是一套**纯人工、离线**的测试套件（标准答案登记表、115 题题库、观察记录表、分析程序、询问信与试点提案模板），**不含任何访问外部系统的程序**。使用前请读 `testkit/README.md` 的行为规则。

```bash
daxin init --ws .daxin
daxin policy import-register testkit/ground_truth_register.xlsx --freeze --by 甲   # 标准答案
daxin observe-import testkit/test_log.xlsx testkit/question_bank.xlsx             # 观察与人工判定
daxin judge && daxin release --by topic,region,channel,language
daxin evidence out/evidence_cards.md --public      # 对外导出：需要 private/institution_map.csv
```

## 新增：出题、覆盖率、制度文件草拟（rules-0.2）

```bash
daxin questions --out out/questions.json     # 冻结标准 → 基础题 / 易混边界题 / 改写题
daxin coverage                               # 有未测事实的主题封顶 L3（完全没测 L4）
daxin accuracy                               # 机器判定对人工复核的准确率、误放行率、kappa（均附区间）
daxin policy draft 制度文件.txt --raw-dir raw --effective-from 2026-01-01   # LLM 草拟，引文逐字核对，只进草稿
```

LLM 经 OpenAI 兼容接口调用（默认 `glm-5.3-flashx`，可用 `DAXIN_LLM_URL`、`DAXIN_LLM_MODEL` 覆盖；密钥只经环境变量 `DAXIN_LLM_KEY` 或网络代理注入，不写入文件）。
草拟结果：引文不在原文中、数字不在引文中、键/比较符/日期不合格的一律拒收；通过的也只是**未确认草稿**，范围字段（产品、地区）不在引文中时标“待核”，没有生效日期时必须由人补。

**实测数字（仿真，单次）**：`testkit/draft_eval/` 里 1 份虚构制度文件、手写答案表 11 项（答案表由 Claude 编写，未经人工复核）。`glm-5.3-flashx`、effort=high 的一次运行：12 条通过核对、0 条拒收；
严格匹配（单位和范围字符串须完全一致）命中 3/11，精确率 0.25、召回 0.27；宽松匹配（忽略“元/天”的周期后缀和“地区”后缀）命中 11/11。
差距几乎全是**范围与单位的写法不统一**（如“R1 地区”对“R1”），说明草拟后必须把范围映射到受控词表再确认。样本只有 1 份文件、11 项、1 次运行，**不能据此推断真实准确率**；`python testkit/draft_eval/run_eval.py` 可离线重放复现。

测试必要性的依据与来源（含哪些没有文献支撑）见 `docs/依据与来源.md`。

## 限制（如实）

- 抽取只覆盖有限句式：阿拉伯数字与中文数字（到 999）、常见单位、百分比；复杂条件、多重否定、表格式回答可能漏判，漏判落入“待人工”。当前只有简体中文规则，英文与葡文为基础单位词，未经系统测试。
- R1–R4 分级、L1–L4 门槛、过期天数均为**示例阈值**，需用试点数据与银行意见校准；影响面是代理指标，不是真实流量。
- 一个工作区对应一个机构代号。
- 尚无任何真实机构的数据；演示中的数字来自仿真。
- 草拟只处理数值型事实；范围字段尚未映射到受控词表；覆盖率以“事实键+范围”为单位，未区分出题类型（基础/边界）是否都测过。
- 观察层目前只支持记录表导入；HTTP 适配器（仅授权测试环境）、REST、网页界面尚未实现。
